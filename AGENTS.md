# Portfolio Demo Recording Guidelines

Use these guidelines when creating a screen recording or product walkthrough for this project or another project that adopts this file.

## Understand the project first

- Read the project documentation and inspect the actual source or UI before recording.
- Identify what the product does, its main user flow, and the options it really supports.
- Demonstrate the real application with representative inputs in an isolated workspace. Do not invent features, output, or user interface behavior.
- Prefer one complete, easy-to-follow workflow: start the product, perform a useful task, show the result, and leave the viewer with a clear next step.
- Keep explanations brief and tied to what is visible. Use on-screen captions when useful; add voiceover only when requested.

## Make the recording feel natural

- Show the product itself as the focus. Avoid turning the walkthrough into a slide deck with oversized headings, progress bars, or decorative panels.
- Type commands and text at a believable human pace. Keep each command on screen while it is entered.
- Let application output appear as the application produces it. Do not reveal terminal output one line at a time with arbitrary delays.
- Use pauses only where a person would naturally read a menu, choose an option, inspect a result, or move to the next task.
- In a terminal recording, keep the cursor solid and steady with blinking disabled. Move it smoothly as text is entered; do not make it blink or flash for each typed character.
- Keep the pointer movement calm and purposeful. Avoid sudden jumps, repeated movement, or cursor effects that distract from the task.
- Make text comfortably readable at the delivered video size and keep the terminal or app frame in view.

## Visual style

- Match the product's platform and existing design where possible. For a requested macOS look, use a restrained macOS desktop and Terminal appearance: menu bar, familiar window controls, a clean terminal profile, and a legible monospaced font.
- Keep transitions subtle. Prefer a continuous recording over frequent scene changes.
- Do not imply a direct device or desktop capture if the footage was reconstructed or rendered. Describe rendered footage accurately when that distinction matters.

## Keep it accurate and reusable

- Verify commands and displayed output against a real run of the project.
- Describe options using the current source or UI, and call out meaningful limits such as templates that contain stubs or empty files.
- Keep demo data generic and avoid exposing personal or sensitive information.
- Save the final video and the smallest useful set of reproducibility notes or capture scripts in a clearly named folder such as `portfolio-demo/`.
- Use a common web-friendly video format such as MP4/H.264 when available. Review the finished video for readability, pacing, clipping, and accidental inaccuracies before delivering it.
